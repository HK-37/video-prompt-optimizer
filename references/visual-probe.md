# 图样探路（visual probe）

> **触发**：`preflight.md` 第 0 项判定题材 / 原型未命中 `character-typology.md`。
> **目的**：把用户「说不清的审美偏好」从形容词变成**可观察的样本选择**，据此定向改提示词；定稿后回填判据库，让下次同题材不再探路。
> **为什么需要它**：维度 × 原型再怎么枚举，也覆盖不了用户个人的审美偏好。那一格只能靠样本让用户指认——这是模板库的兜底，不是替代。
> **交付物定义**：探路的交付物是**可迁移的提示词**；出图是**可选抽检**，不是交付节点。用户没明确要求时不主动出图，也不追问版式命名（设定集 / 海报等）。

## 第 0 步 · 先确认（硬约束，不可跳过）

**开搜图片之前必须向用户确认**，且按用户约定一次性列全、不逐项问：

1. 搜图范围（题材 / 风格 / 年代 / 媒介）
2. 数量（默认 30–50 张）
3. 是否消耗额度（搜图本身不生成；若要出方向性样张才消耗）
4. 版权边界（只作人眼分析，不喂模型、不上传、不入库）
5. 预计耗时

用户回「就这么办」才开搜。**未经确认不得发起任何搜图动作。**

## 第 1 步 · 按维度分层取样

- 按 `character-typology.md` 的 10 维分层：每维至少 2 张正例 + 2 张反例，跨风格（写实 / 插画 / 传统绘画 / 影视 / 概念设计）。
- 落盘到独立调研目录，**不进 `素材库/`**；写 manifest（来源 / 查询词 / 许可）与分组缩略图拼板。
- 先目检剔噪再给用户看。**相关样本不足 20 张时走降级分支**（见末节）。

## 第 2 步 · 结构化选型（成败关键）

不问「哪张好」，给用户一张表逐图填：

| 图号 | 选 / 不选 | 命中的点（落到维度） | 不合适的点（落到维度） |
|---|---|---|---|
| 示例 T_09 | 选 | 头部：束发露额；服装：白描衣纹利落 | 武器：不是长刀 |
| 示例 A_11 | 不选 | — | 头部：全包只露眼 → 刺客；眼神：不可读 |

规则：

- 至少 **3 选 3 不选**。
- 「感觉不对 / 不够帅 / 太丑」必须追到维度（10 维之一）；表里没有的维度**就新加一列**——用户新说出的维度，本身就是判据库该补的那一行。
- 用户只给笼统评价时，按维度逐项追问，一次列全，不一项一项问。**笼统褒义词（好看 / 帅 / 英气 / 不对味）先回指已定位的具体缺陷，不另立审美风格轴**；只有用户明确对比两个方向时才建轴。
- **先分「内容层」与「载体层」**：参考图里的造型、姿态、构图、配色属内容层，**默认要迁移**；媒介、材质、画质、做旧、水印、拍摄方式属载体层，是雕像 / 手办 / 数字分身 / 手机截图自带的副作用，**默认不迁移**。只有多张参考共享某载体特征、且用户明确说「就要这个质感」时才写进提示词。
- **比较级形容先做并排定位**：用户说「太写实 / 不够风格化 / 差点意思」时，先把自己出的图与参考图并排，判断差异落在内容层还是载体层，再动手。**载体特征在多张参考里重复出现，只说明它们共享同一媒介，不等于需求目标**；典型误判是把模型雕塑 / 数字分身自带的哑光材质当成风格目标，而实际要迁移的是造型。中性特征对照见 `visual-negative-examples.md` 对照 5。

## 第 3 步 · 差异归因 → 定向改词

| 反馈类型 | 处理方式 |
|---|---|
| 满意点 | 翻成**正向画面语言**（身体部位 + 精确状态 + 参照物）写进正文 |
| 不满意点，能从正文删 / 换 | 改正文：动词展开、部件写死、覆盖范围写具体 |
| 不满意点，只能作排除项 | 进平台负向框；**正文永不写「不要 / 没有 / 别」** |

- 每条改动记进 `templates.md` 附录的改写对照表（原话 / 优化后 / 改动类型 / 具体理由 / 原意校验）。
- **只改被点名的维度**，其余一字不动。否则这轮改好、下轮又崩；未被点名的维度一律不动，是这套流程的收敛条件。
- 用户要「几组不同取向」时，走**变体轴**（锁骨架、每条放开 1 个非关键维度），别用同一条提示词重复采样充数；两者区别见 `visual-negative-examples.md` 对照 6。
- 需要抽检时先出 **1 张**、不批量；对照用户选中图逐维核对，报「命中 / 未命中 / 需确认」。**用户未要求出图则跳过本条**，直接交付提示词。

## 第 4 步 · 收口与回填

- 探路**最多 2 轮**。第 2 轮仍不命中 → 停下，判定属于 ①需求本身有张力 ②搜图通道上限 ③模型能力上限，列选项让用户决策，**不再自行加轮次**。
- 定稿后把满意 / 不满意点回填成 `character-typology.md` 的一行（题材 → 原型 → 维度 → 必检项 → ❌ 常见混写），并同步 `preflight.md` 命中清单、`SKILL.md` 索引、`ROADMAP.md` 计数。
- **闭环判据**：下次同题材在 `preflight.md` 第 0 项直接命中，跳过全部探路。

## 降级分支（通道受限时）

通道可用性实测（结果可能随时间变化，每次探路前复查）：部分通用图片搜索返回 502 / JS 挑战页 / 404 / 空结果，稳定可用的通常是 **Wikimedia Commons API** 与 **Wikipedia 条目插图**。Commons 全文检索噪声极大，需分类 + `intitle:` 限定；批量请求**必带 `action=query`**（漏掉会全部返回非 JSON）。

- 相关样本 **< 20 张时不硬凑噪声**：改为「项目已有素材库图 + 生成 3–4 张方向性样张让用户选」，或明确报告缺口并停下。
- 商业角色设定图（游戏概念 / 影视海报）在开放图库常**零命中**，属正常，不要用无关图冒充。

## 版权边界（项目约定）

探路图**只作人眼视觉分析**：不进 `素材库/`、不上传即梦、不作 i2i 参考图、不喂生成模型（版权风险 + 触发 10940）。逐张许可见来源文件页。

## 维护

新增通道、新的降级条件、新的反馈维度时改本文件；同步 `STRUCTURE.md` 路由表。**不要**把「先确认」这条降级成建议——它是用户明确设的硬约束。
