## 一、第一原则：这个 skill 只管「表达」，不碰「创意」

一条提示词里藏着两种信息，分清楚才不越界：

| | 定义 | 谁的活 |
|---|---|---|
| **创意（想法）** | 拍谁、拍什么事、想传达什么情绪 | **用户（导演）**——skill 一个字都不替他定 |
| **表达（说法）** | 把已经想好的画面，翻译成模型听得懂的话 | **skill**——这就是本 skill 的全部职责 |

地图的两根轴，都是「表达」，不是「创意」：
- **横轴 = 镜头表达**（怎么拍：机位/运镜/光/调色，摄影指导的活）
- **纵轴 = 内容表达**（画面里有什么：器物/动作/环境元素，用准词说清）

**氛围是两轴合力兑现的**：纵轴给"荒凉的证据"（破桌、浮尘），横轴给"荒凉的语气"（冷调、大远景、静止）。缺一边都不成立。

## 二、总则铁律（写进 SKILL.md 硬约束）

> **只增强，不新增。**
> 换准词、加质感——放手做（这是纯优化，零越界）。
> 要往画面里加用户没提过的**新实体/新风格**（花瓶、乌鸦、青橙调）——**先说一声让用户定**，不默默塞进提示词。

边界线就是**用户给的实体清单**：只能在用户已提到的对象上加形容词/质感/动作，不能凭空多一个名词。

配套原则：
- **极简 / 留白场景反向工作**：用户点名"极简""只要一桌一椅"时，skill 不但不加料，还要帮他**减到位**（剔多余默认物件、强调负空间）。宁可少给，不可多塞——留白和负空间本身就是风格化表达，不是"缺内容"。
- **输出必过用户这关**：skill 吐的提示词是给用户看的、用户认不认自己会说，不是偷偷拿去跑。所以体验细节（默认开关、何时提议补元素）**不预先写死，留给实跑迭代校准**。

## 五、Viral Looks 的处置（整类不进地图）

Viral Looks（44 条网红梗）**不是镜头技法，是有保质期的"成品皮肤"**（火三个月就过气）。决策：
- **不进横轴**——固化进 skill 当天就是旧的，还会腐烂、要人追着维护，违背"只收能长期复用的"。
- ✅ **已建 `references/viral-decode.md`（2026-11-04）**：教「遇到爆款 → 联网现查正名与原版 / 二创形态 → 拆成画面零件 → 翻成调度语言 → 回落词库与模板」。**只存拆解手法 + 现查入口，不存具体梗清单**；另含一次匿名实跑演示、边界与生成前自检。具体梗名 / 别名考据 / BGM 版本 / 成片路径仍记在**使用者项目 memory**。
- **暂不拆独立爬取工具**——等真高频做爆款、需要定时盯榜时，再单起带定时任务的爬取 Agent。现在需求没到。
