# 生成前预检（preflight）

> **定位**：出稿前逐项打勾。把散落在 `SKILL.md`「开工前先查」、第 4.6 步、`audit-avoidance.md` 生成前自检 6 项、`templates.md` 审核自检 6 项、硬约束区里的检查收敛成一张按序执行的表。
> **入口闸**：先完成 `SKILL.md` 第 0.0 步的创作用途与交付前置，再进入下方题材分支；「用户想优化提示词」只是任务类型，不等于作品用途。

## 创作用途前置（第 0.0 步回查）

| 必登记项 | 通过标准 |
|---|---|
| 作品用途与目标 | 已知道做着玩 / 自媒体 / 宣传 / 叙事 / 投放等哪一类，以及怎样算完成 |
| 发布渠道与受众 | 已知道在哪发、给谁看、目标观众体验；未公开与公开发布不共用默认尺度 |
| 创作工具与执行者 | 已知道具体产品 / 功能、由谁生成；平台能力不凭模型名臆测 |
| 形象与素材来源 | 本人 / 授权形象 / 原创虚构已分清；参考图、分身或设定能否使用已明确 |
| 核心体验与风格强度 | 已知道最该被记住的效果、夸张程度和不应变成什么 |
| 交付限制 | 单条 / 分镜、时长、画幅、台词音轨、分次生成与后期接受度已登记 |

用户已给的信息不重复问；缺项若改变方案，先声明默认打算，再一次性集中问全。若任一空会改变身份一致性、画幅、风格或交付结构，**不得直接进入提示词改写**。

## 创作路线与实现方式前置（2026-11-13 新增）

| 判定 | 动作 |
|---|---|
| 多种实现路线会实质改变结果（修图 / 拍摄条件 / 表演妆造、分镜 / 连续表演等） | 给 2–4 个可感知差异的路线选项；推荐可放第一并标「推荐」，再集中问最多 1–3 组「路线 / 强度 / 不可变项 / 输入类型」。用户选择前不写完整优化稿 |
| 路线、强度、保留项和输入已明确，或仅修错别字/参数等技术错误 | 直接做，不为提问而提问，不重写创作内容 |
| 用户要求「先给一版默认的」 | 给可修改的推荐版本，标「待确认假设」，列出假设被否时会影响哪些改写项 |
| 用户选择修图 / P图路线 | 主变量为皮肤、脸型、发型、质感、妆造与指定保留项；机位/焦段/布光只在辅助需要时补，不主导 |
| 用户选择夸张 / 自嘲 / 强风格 | 特效与夸张按明确目标大胆用，不把「自然克制」当更高审美；每个特效须有功能分工 |
| 身份 / 产品 / 构图 / 服化为不可变项 | 登记同一首帧 / 同源派生 / 数字分身 / 原照片及授权状态；文字「同一人」不能独立承担跨请求保真 |
| 手指与五官、物体插入、前后遮挡是核心证据 | 出图后必须裁切放大核验遮挡，再判成立；不依赖整图或图像描述回传文字；连续两次做不到换模型/渠道或换实现方式 |

案例参照 `experience-self-comparison.md`，但案例中的角色、具体特效和模型表现不得直接套用到新任务。

## 第 0 项 · 分支判断（最先做，决定走哪条路）
> **分工**：`templates.md` 是填空骨架（写稿用），本表是查错清单（检查用）；`scripts/lint_prompt.py` 只做机械断言（否定句 / 运镜 / 守卫词），本表做**语义判断**（造型判据 / 审核雷区 / 方位锚）。语义判断不进 lint 词表，这是第四轮架构修正后的定论。

## 第 0 项 · 分支判断（最先做，决定走哪条路）

| 判定 | 动作 |
|---|---|
| 题材 / 角色原型**命中** `character-typology.md` | 读取该行「必须写进画面的证据」，逐维落进提示词 → 继续下面第 1–9 项 |
| 题材 / 原型**未命中**，或用户风格描述无法落到已知维度 | **转 `visual-probe.md`**：先向用户确认，再搜图探路；定稿回填判据库一行后回到本表 |
| 用户明确要求「先看参考图再定」 | 一律走 `visual-probe.md`，即使判据库已命中 |
| 用户说「生几组 / 多来几张看看」 | 先区分要**同词抽卡**还是**不同取向的变体**；变体锁骨架、每条只放开 1 个非关键维度，见 `visual-negative-examples.md` 对照 6 |

## 评价 / 对比 / 评审类任务（额外四条纪律）

> 触发：用户要求评价、比较、评审、选型、诊断。这类任务最容易把「揣测对方期待」放进判断输入；四条必跑，特征组合见 `visual-negative-examples.md` 对照 8。

1. **事实与判断物理分开**：先列可观察事实清单，再列价值判断，两段不混写。
2. **声明评价标准**：开工前写明本任务采用哪套审美 / 技术标准，中途不擅自换标准。
3. **无判据就降级声明**：找不到可枚举维度时，明确说「这是个人观感，不是客观结论」，不包装成评审报告。
4. **不用旧诊断套新对象**：单一会话内不拿自己此前的结论替代当期观察，防确认偏误。

评价前先查 `visual-negative-examples.md` 定位差异落在哪个维度；改词时只改被点名的维度。

## 出稿后

对每条最终提示词跑 `scripts/lint_prompt.py`，把通过率与未过项报给用户（`SKILL.md` 质量检验节）。**静态图提示词的运镜维度不适用**，出现「缺运镜」时如实标注，不要为了凑分硬加运镜词。

**结果验收与 lint 分开**：至少分「原始目标 / 身份保真 / 结构 / 动作与遮挡 / 气质调性 / 时序一致性 / 画质 / 输入可行性」记录「通过 / 失败 / 无法判定」。核心项失败不得被画质或局部改善抵消；遮挡类没有放大核验时标「无法判定」，不得写「通过」。

## 维护

新增检查项时先问：它是**机械断言**（可静态判定）还是**语义判断**？前者才考虑进 `lint_prompt.py` 并同步 `tests/README.md` 与基线；后者留在本表，由执行 skill 的 LLM 按 references 判。`visual-dimension-glossary.md`（维度词典）与 `visual-negative-examples.md`（易混对照）属语义查表层，不进 lint。
