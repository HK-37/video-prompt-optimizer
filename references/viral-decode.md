# 爆款运镜 / 网红视觉梗的拆解方法（viral-decode）

> **实测基线**：本页方法与演示来自 2026-11-04 一次「群像逐次入画」爆款运镜的完整复现实跑
> （文生视频模型，版本未精确记录）；相关协议事实另核自厂商官方 API 文档（2026-11-04）。
> 模型能力与平台封装会漂移，具体能力结论以现查为准。

> **这是什么**：遇到"就前几个月挺火那个运镜"这类**只给花名、不给画面**的需求时，
> 把爆款成品拆成可复用零件，再回落到本 skill 已有的词库 / 12 维 / 模板。
> **本页只存拆解手法，不存爆款清单**——梗有保质期，固化进 skill 当天就是旧的
> （决策见 `content-map.md` 第五节）。

## 一、为什么不能直接写花名

模型训练字幕里没有「某某运镜」「某某同款」这种词条。花名是**社交平台的检索标签**，
不是画面语言：写进正文既不会被识别，还会把梗名 / BGM 名这类无关词混进检索，稀释主动态权重。
**花名只用来跟人沟通，不用来跟模型沟通。**

同理，配的 BGM 名、平台标签、发起者名字、爆火时间都属于**成品皮肤**，不进提示词。
BGM 与卡点是后期的事（见 `ROADMAP.md` 定位边界），本 skill 不处理。

## 二、四步拆解法

### 第 1 步：现查，别凭记忆

爆款梗的名称、起源、形态**会漂移**，且常有多个别名指向不同东西。联网核三件事：
① 正名与各别名分别指向什么；② 原版形态；③ 有没有被 AI 二创改造过。

**最易踩的坑：把二创形态当原版。** 本次实跑中，原版是"人先站定、镜头匀速环绕扫过、被扫到才抬眼"，
AI 二创版为适配别的题材改成了"前景遮挡 → 焦点转移 → 角色逐个近景入画 → 后拉群像定格"。
两者调度结构不同；用户描述的往往是二创版。**先确认要哪一版**，再拆。

名称考据里还有一类"拿 BGM 代称运镜""拿导演名归名"的民间叫法，都不是运镜术语，
只用于检索，不进正文。

### 第 2 步：拆成画面零件

把成品拆到「能写进 12 维清单」的粒度，通常五件：

| 零件 | 落到哪 | 本次示例（匿名化） |
|---|---|---|
| 起幅 / 终幅构图 | 景别 + 构图（`cinematography-checklist.md`） | 单人中近景 → 四人三角梯形全景 |
| 遮挡与转场 | 机内效果 + 主体调度 | 极近前景横向走过、短暂遮满画面 |
| 摄影机路径 | 运镜（维度 3） | `Dolly out + Arc left`（后拉 + 左弧环绕） |
| 主体调度节拍 | 时间运动 + 分镜（`shot-continuity.md`） | 每段只引入一个新角色，1→2→3→4 |
| 视线 / 表情节拍 | 气质词→身体语言（`word-bank.md` 三·B） | 镜头掠过谁，谁才抬眼看镜头 |

**拆完的标志**：每个零件都能用一句**可见的物理描述**写出来，且不含任何专名。

### 第 3 步：翻译成调度语言

花名 → 术语对照（示例）：

| 大白话 / 花名 | 写进提示词 |
|---|---|
| "镜头绕一圈" | `平稳弧形环绕，前景与背景出现明显的横向视差` |
| "人物一个个出来" | `每段只引入一个新角色；【B】从极近前景横向走过，形成自然的前景遮挡转场` |
| "最后大家一起看镜头" | `末段机位完全稳定，全员斜瞟镜头`（视线统一要靠**尾帧锚图**硬锁，见第 4 步） |
| "氛围很拽 / 贱兮兮" | `眯眼、歪头、单侧嘴角上扬、斜瞟镜头、舌尖微吐`（抽象气质词翻可见身体语言） |
| "谁站 C 位" | `【B】位于画面中央最前方，【A】在左后方，【C】在右后方`（镜头坐标，不用角色坐标） |

### 第 4 步：回落 skill 已有能力

- **多段落** → `shot-continuity.md` 第四节 + 四·补（时序控制三层辨析）、模板 5
- **群像逐次入画** → `templates.md` 模板 11
- **终点站位 / 统一视线** → 必须出**尾帧锚图硬锁**，见 `shot-continuity.md` 三·补
- **造型一致** → 定妆图 / 同源派生（三、六·补2）
- 补镜头 → 12 维清单；审核 → `audit-avoidance.md`；负向 → `SKILL.md` 第 4.5 步

## 三、一次实跑演示（匿名，2026-11-04）

某"群像逐次入画"爆款运镜，用户只给了三个互相矛盾的花名和一句 BGM 描述。
按四步拆开后，产物是：

- **骨架**：`0-1.5s 单人起幅 → 1.5-3s 前景遮挡 → 3-7s 后拉左弧环绕 + 第三人入画 → 7-10s 第四人入画 + 群像定格`（秒级分镜表，实测按序落地）
- **护栏**：每段只引入一个新角色；主位显式交接（"【A】顺势退到侧后方，把画面主位完整交给【B】"）；终点站位写死镜头坐标
- **逐人节拍**："镜头掠过谁，谁才抬眼看镜头，依次点亮"
- **锚图**：尾帧群像图 + 由它 i2i 派生的起幅单人图，成对送首尾帧

**验收结论（逐帧）**：数量 1→2→3→4 严格递增、造型跨段一致、一镜到底无切镜。
纯文字写死的终点站位在**纯文生版没有执行**，换成尾帧锚图后一次到位。
但**弧形环绕的视差感仍偏弱**——单条 10s 长镜头有机位自由度上限，
措辞再强也修不出来，要拆两条 5s 拼（见 `shot-continuity.md` 四·补）。

> 具体梗名、别名考据、BGM 版本、成片与脚本路径、私有网关参数，都记在**使用者项目 memory**，
> 不进本 skill（有保质期 / 私有）。本页只留可迁移的拆法。

## 四、边界与自检

- ❌ 不建「爆款清单」「运镜百科」——三个月就腐烂，且要人追着维护。
- ❌ 不把 BGM / 卡点 / 去水印 / 抽帧验收写进来——属后期，越 skill 定位边界。
- ❌ 不把花名、BGM 名、平台标签写进提示词正文（见 `SKILL.md` 硬约束 15）。
- ✅ 每次遇到新爆款，**现查 → 现拆 → 用完即弃**，只把新出现的"拆法"补回本页。

**生成前自检**：

- [ ] 已联网确认正名 / 原版 / 二创形态，并确认用户要哪一版
- [ ] 提示词正文里没有任何专名（梗名 / BGM 名 / 人名 / 平台标签）
- [ ] 每个零件都翻成了可见物理描述，能落进 12 维某维
- [ ] 终点静态几何（站位 / 视线）已配尾帧锚图，没指望文字写死
- [ ] 已按目标模型确认时序写法（见 `shot-continuity.md` 四·补）
