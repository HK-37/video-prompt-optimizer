# tests/ — 提示词质量的工程检验体系

> 目的：让 skill 的每一次迭代**可测量**，而不是"感觉好像变好了"。
> 没有基线，改规则就是赌博——可能改好 3 条、悄悄弄坏 2 条而不自知。这套东西就是防这个。

---

## 一、两层校验（缺一不可）

### 第 1 层：静态 lint（免费·可全量·每次必跑）

扫描"提示词文本"，断言**可确定的属性**（不是内容对不对，那没法断言）。对应 `scripts/lint_prompt.py`。

检查项（7 条机械断言，加权计分；语义判断归 LLM，见 SKILL.md 第四轮架构修正）：

| 规则 ID | 断言 | 权重 | skill 依据 |
|---|---|---|---|
| NEG_NEGATION | 正文无"不要/别/不能…"否定句式 | 2 | 硬约束 11 |
| EDIT_TERMS | 无 BGM/配乐/定格/闪白/转场等剪辑台指令 | 2 | 硬约束 7、9 |
| SHOT_SIZE | 有景别（必补） | 1 | 12 维清单 |
| CAMERA_MOVE | 运镜只出现一种（必补） | 2 | 硬约束 2 |
| LIGHT | 光线有来源（必补） | 1 | 12 维清单 |
| TONE | 有色调（必补） | 1 | 12 维清单 |
| GUARD | 正向守卫词 ≤ 4 条 | 1 | 第 4.5 步 |

输出 = 加权通过率分数（0-100%）+ 逐条 pass/fail。**分数不是"好坏分"**，是"硬规则符合率"，用于回归对比。

### 第 2 层：渲染抽检（贵·小样本·人工/视觉打分）

静态 lint 查不出"画面好不好"。每轮重要改动后，挑 5~10 条真跑生成，按 rubric 人工打分，记录到 `runs/YYYY-MM-DD.md`：

| 评分项 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 空间关系 | 错乱（如两人跑到同侧） | 大致对但有歧义 | 完全正确 |
| 人物完整 | 明显崩坏/多肢 | 轻微畸变 | 正常 |
| 审核 | 被拦（20111/10940） | 重试过 | 一次过 |
| 质感达标 | 平平无奇 | 尚可 | 电影感强 |

---

## 二、两个长期指标（比单次分数更重要）

迭代是否真的进步，看这两条曲线的趋势，而不是某一版的 lint 分：

1. **审核一次通过率** = 一次过审条数 / 总提交条数（越接近 100% 越省积分）
2. **首轮出片可用率** = 不用重跑就能用的条数 / 总生成条数

在 `runs/` 里每次记一行，画出来就知道 skill 是在变好还是变差。

## 三、工作流

### 首次建立基线
```bash
python scripts/run_regression.py --update-baseline
```
把当前 6 条用例的分数冻结成 `baseline.json`。

### 每次改完 skill / 改完 lint 规则
```bash
python scripts/run_regression.py
```
- 输出每条用例的 基线 vs 当前 vs 变化（↑/↓/持平）
- **有回归（分数掉/新增失败）→ 退出码 1**，当场发现
- 确认改善符合预期后，`--update-baseline` 固化新基线

### 单独检查一条随手写的提示词
```bash
python scripts/lint_prompt.py 我的提示词.txt
# 或
echo "提示词…" | python scripts/lint_prompt.py -
```

## 四、用例说明（tests/cases/）

| 文件 | 类型 | 用途 |
|---|---|---|
| `mecha_cast.txt` | 正面·机甲施法 | 老项目基准，防重构时弄坏 |
| `door_duel_mirror.txt` | 正面·隔门对峙 | 多镜对峙核心场景 |
| `crime_confront.txt` | 正面·犯罪对峙 | 双人空间调度 |
| `daily_empty.txt` | 正面·日常空镜 | 非人物、非机甲场景 |
| `NEG_bad_example.txt` | **反面** | 校验 lint 能抓出 7 类错（应保持低分） |
| `NEG_multi_move.txt` | **反面** | 校验能抓"运镜不单一"（应保持 fail） |

**反面用例必须一直处于低分**——如果哪天反面用例突然变高分了，说明 lint 规则被改松了、变成橡皮章，要立刻警惕。

### 新增用例
直接把一条提示词存成 `tests/cases/名字.txt` 即可，回归脚本自动收录。建议每来一个新题材/新翻车案例，就沉淀一条。

---

## 五、局限（诚实说明）

- **静态 lint 只查硬规则**，查不出"光影美不美""节奏好不好""创意强不强"——那些靠第 2 层和你的眼睛。
- **关键词表是启发式**，会有误判（如把普通用词当敏感词）。发现误判就修 `lint_prompt.py` 的词表，**修完记得重跑回归**确认不误伤其他用例。
- **渲染抽检样本小**，只能反映趋势，不能保证统计显著。它的价值是"发现明显退步"，不是"精确排名"。
- **无第三方依赖**，纯 Python3 标准库，任何装了 Python3 的机器直接跑（实测 Python 3.13）。
