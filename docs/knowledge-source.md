# 知识源配置与加载边界

## 设计原则

Skill 是公开的规则与方法，知识库是独立的数据资产。普通 `git clone` 只会获得 Skill 自身，**不会自动获得用户配置的外部知识库**。

这样可以使用公开或私有的知识源，而不把知识正文、个人路径或访问凭据提交到公开仓库。

## 目录式知识源

维护者可将 Markdown 知识库放在本机任意受控位置，并在宿主的项目配置中登记：

```text
知识库根目录/
├── kb/MOC-index.md          # 先读索引，确定相关主题
├── kb/20-影视知识/          # 按需读取相关条目
└── evidence/                # 可选的证据与框架
```

宿主的项目配置可记录“创作知识库路径”，但实际字段名取决于宿主产品，**本项目不假定所有 Agent 都识别同一个环境变量**。执行者应在当前宿主中确认如何向 Agent 提供该目录；不要把它写死成某个开发者的绝对路径。

推荐流程：

1. 先检查知识库是否存在、当前 Agent 是否有读取权限。
2. 读取索引，按任务选择相关条目，而非每次加载全库。
3. 区分来源命题、项目转译、验收条件与不适用条件。
4. 只把适用知识转成提示词或验收建议；模型能力仍查对应官方文档。
5. 没有知识库时，明确降级为公开规则，不虚构读取结果。

## 远程知识源

也可由宿主提供受控 API 或内部检索工具。此时凭据放在宿主的私有配置或密钥管理系统中，**不能写入本仓库、提示词正文或输出示例**。

本仓库目前不包含远程检索服务或生产级向量数据库实现，不声称脚本已完成语义检索。目录读取与知识选择由调用本 Skill 的 Agent 执行。

## 权限与可用性

- 公开仓库不会向用户授予任何私有知识库的访问权限。
- 私有仓库的访问权限需要另外授予；普通用户无权克隆时，不应把它注册为强制子模块。
- 私有知识源可以是正常工作的可选增强能力，但开源项目必须明确其降级行为。
- 引用来源不自动授予复制、修改或再分发权利；知识源分发与 Skill 的开源许可证分别处理。
