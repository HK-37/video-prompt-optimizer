# 知识源配置与加载协议

## 设计原则

本 Skill 与公开的体系化知识库深度结合：**Skill 负责转译方法，知识库负责创作专业判断。** 两者分仓库、分许可维护，但属于完整的知识驱动工作流。

知识库地址：https://github.com/HK-37/image-video-creation-knowledge

- Skill：MIT。
- 知识库：CC BY 4.0，署名 HK-37。
- 第三方来源：保留各自权利，不随上述许可重新授权。

普通 `git clone` 只下载当前仓库，**不会自动克隆另一个知识库**。这与前端引用 CDN 不同：当前实现是 Agent 读取本地 Markdown 文件，不是浏览器运行时自动下载远程脚本。

## 安装知识库

推荐将两个仓库放在独立目录：

```text
your-workspace/
├── skills/video-prompt-optimizer/
└── knowledge/image-video-creation/
```

在 `knowledge/image-video-creation/` 目录执行：

```bash
git clone --branch v1.1.0 --depth 1 https://github.com/HK-37/image-video-creation-knowledge.git .
```

如果父目录已有文件，应先确认目标目录为空；不要覆盖自己的项目文件。也可将公开知识库添加为项目子模块，或使用宿主支持的数据依赖机制，但这些方式都需要相应的初始化／更新步骤。

## Agent 如何加载

宿主配置中登记“创作知识库路径”，指向上述 `knowledge/image-video-creation/`。字段名称取决于宿主产品，本 Skill 不假定所有 Agent 都识别同一环境变量，也不写死开发者的绝对路径。

执行流程：

1. 检查目录与 `kb/MOC-index.md` 是否存在，记录知识库版本。
2. 先读索引，按任务选择相关条目，而不是每次加载全库。
3. 读取条目的来源命题、项目转译、可观察验收与不适用条件。
4. 用知识决定提示词优化方向、参考输入和验收建议，不只把知识库当引用列表。
5. 涉及具体模型功能时，仍查该模型官方文档；知识库不能替代接口参数。
6. 输出或分发知识条目时，保留 HK-37 署名、知识库链接、CC BY 4.0 链接及修改说明。

未配置知识库时，可继续使用本仓库的公开参考文件，但必须明确提示“未启用体系化知识增强”，不得宣称已经完成知识库驱动的优化。

## 版本与许可

建议固定到明确标签，例如 `v1.1.0`，而不是长期跟随不可控的最新提交。更新后应重新检查链接、条目结构、许可声明与 Skill 回归。

知识库中的公开 URL 用于原始资料回查。复制或改编知识库内容时，要区分本项目可授权的整理与原创表达，和第三方教材、论文、网页的原始权利。不得因为知识库采用 CC BY 4.0，就复制第三方原文、图表或课程材料。

## 远程服务（可选）

如未来有知识服务，可由宿主通过受控 API 使用。当前仓库不包含生产级检索服务或向量数据库，不声称已实现服务端语义检索。现阶段由 Agent 按上述目录协议读取和选择知识。
